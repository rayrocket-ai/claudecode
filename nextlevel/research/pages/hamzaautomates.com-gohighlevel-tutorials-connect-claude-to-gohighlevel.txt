In Claude Code it's one command, claude mcp add --transport http leadconnector with that same URL, and a browser opens to sign you in the first time you use it.

Short version
01Use HighLevel's own MCP server. Claude.ai, the desktop app, Cowork and Claude Code all use the same URL: services.leadconnectorhq.com/mcp/anthropic/v2.
02It signs in with OAuth, so you don't need a Private Integration token for Claude. Tokens are for the older /mcp/ endpoint, n8n and your own scripts.
03More than 550 operations across 38 areas: contacts, conversations, opportunities, calendars, social posts, blogs, emails, invoices and more. Forms and surveys are read only.

Connect Claude (web, desktop app and Cowork)
01
Open connectors in Claude
In claude.ai or the Claude desktop app go to Customize > Connectors. HighLevel's doc still calls it Settings > Connectors, same place. Custom connectors work on every Claude plan, but the Free plan is limited to one.
02
Add a custom connector
Click + Add, then Add custom connector. Give it any name (I literally called mine something like "GoHighLevel MCP for Claude"), paste https://services.leadconnectorhq.com/mcp/anthropic/v2 as the URL and click Continue.
03
Leave the sign-in settings on OAuth
Claude detects the authentication for you. Keep the sign-in option and don't add a request header. HighLevel's connection is OAuth, no token to paste. Click Add.
04
Sign in to HighLevel and pick the sub-account
A LeadConnector sign-in window opens. Log in, choose the sub-account you want Claude in (start with a test one), review the permissions and approve.
05
Turn it on in a new chat
Start a new chat, click + at the bottom left, open Connectors and make sure the HighLevel one is toggled on. Cowork uses the same connector.
06
Test it with a read-only question
Ask "Find the last 5 contacts I added in HighLevel." That's HighLevel's own test prompt, and it can't change anything. If you connected as an agency with several sub-accounts, name the sub-account in the question.
On a Claude Team or Enterprise plan
Members can't add custom connectors themselves. An Owner or Primary Owner goes to Organization settings > Connectors > Add > Custom > Web and adds the same URL. Then each person goes to Customize > Connectors, finds it and clicks Connect, which runs their own HighLevel sign-in, so everyone only gets the sub-accounts and permissions they approve.
How to connect Claude Code to GoHighLevel
Run this in your terminal: claude mcp add --transport http leadconnector https://services.leadconnectorhq.com/mcp/anthropic/v2. Add --scope user if you want it in every project, otherwise it only loads in the folder you ran it in.
Then open Claude Code and type /mcp, pick leadconnector and finish the browser sign-in (or run claude mcp login leadconnector from the shell). claude mcp list should show it as Connected. If it says Needs authentication, you skipped the sign-in.
You can also put it in a .mcp.json file at the project root with "type": "http" and the URL, which is handy if your team shares a repo. Everyone still signs in with their own HighLevel login. Don't put an Authorization header in there: if a header gets rejected, Claude Code won't fall back to the OAuth sign-in.
To disconnect properly, run claude mcp logout leadconnector before claude mcp remove leadconnector. Removing it on its own only deletes the local copy of the login.
What the GoHighLevel MCP can read and write (Oct 2026)
The server gives Claude four tools: list_locations, search_operations, describe_operation and execute_operation. Behind them sit more than 550 operations across 38 areas of HighLevel. Claude searches for the operation it needs, reads its inputs and safety notes, then runs it, which is why you see four tools in Claude and not hundreds.
What it can actually do depends on the permissions you approved. If you're not sure, ask Claude to use search_operations for the thing you want. If it's not in the catalog, it can't do it.

Can Claude build GoHighLevel workflows?
Yes, but only in private beta right now. HighLevel added workflows to the MCP server on October 28, 2026, after a request for exactly this ("Claude > GHL workflow automations (write)") sat at 399 votes on their ideas board. Claude can find a workflow, read its triggers and steps, build one from a description, publish it, delete it, read the execution logs and count enrollments and failures per step.
It only works in sub-accounts enabled for the Workflows API. Everywhere else Claude gets WORKFLOW_API_NOT_ENABLED_FOR_LOCATION, and you join the beta through HighLevel support or the form linked in their changelog. Back in June I said in my video it would soon be able to create automations, and here we are.
The rules to know before you let it touch a live workflow: new workflows are always saved as drafts, and publishing is a separate request. To change a published workflow it gets set back to draft first, which turns its triggers off and pauses everyone in it at their next step until it's published again. An update replaces the whole workflow, and if someone is editing it in the builder at the same time the update gets rejected. Deleting is permanent and stops everyone in it.
Logs cover up to 30 days per request and go back 60 days. They only show live runs, so contacts you pushed through with Test workflow won't appear. My favourite use is the boring one: ask which steps failed this week and for whom. For how workflows are built by hand, see GoHighLevel workflows.
Do you need a Private Integration token?
Not for Claude. HighLevel's own FAQ says the Claude, ChatGPT and Cursor connections use OAuth, so you don't create or rotate a token. HighLevel also says OAuth gets a wider set of permissions than a token does.
You'd use a Private Integration token for the older universal endpoint (https://services.leadconnectorhq.com/mcp/), which works with any MCP client but has a smaller set of tools and one sub-account per connection, and for n8n, where HighLevel's example passes the token as Authorization: Bearer plus a locationId header. A lot of the guides ranking for this still only teach that older setup.
If you do need one: in the sub-account go to Settings > Private Integrations (if it's missing, check Labs), click Create new Integration, name it after what it's for, tick only the scopes that job needs, and copy the token straight away because HighLevel only shows it once. You can have up to 20 per sub-account and 20 at the agency level, so give each tool its own.
HighLevel recommends rotating tokens every 90 days. Rotate and expire this token later gives you 7 days where the old and new token both work. If a token leaks, use Rotate and expire this token now. You can edit a token's scopes later without generating a new one. In Claude Code, keep it out of a shared .mcp.json by using an environment variable like ${GHL_TOKEN} in the header.
Multiple sub-accounts and white label
A normal connection is tied to the one sub-account you pick at sign-in. Agency connections that cover several sub-accounts are rolling out: if your sign-in screen lets you choose more than one, you have it, and you just name the client in the prompt ("in Downtown Clinic, list contacts tagged vip"). Every request still runs in one sub-account, and Claude can't reach a sub-account you didn't select.
It works on a white-labelled account. Mine is Hexona Systems, and the Social Planner you see in the video is my white-label version. The sign-in screen is the LeadConnector one, so if a client connects their own Claude, that's the name they'll see. More on that setup in White label guide.
How to use it without breaking a client's account
Connect a test sub-account first. Build a sandbox with fake contacts and a copy of your workflows, and let Claude loose there before it ever sees a client. I didn't even reconnect mine on camera because I didn't want it to mess up the one I already had.
Approve only the permissions you need. On the consent screen, if the job is reporting, leave the send and delete permissions off. For workflows, reading, changing, publishing, deleting and reading logs are each separate permissions, so you can give Claude read access and the logs without letting it publish.
Be careful with Always allow. Claude asks before it runs a tool, and you can pick allow once or always allow. Always allow on read tools is fine. On sending messages, deleting or anything with payments, approve each one. HighLevel adds its own confirmation on deletes and other irreversible actions too.
Use the official server. There are a bunch of community GoHighLevel MCP servers on GitHub, and some of their setup guides tell you to tick every read and write scope on your token. Anthropic's own docs warn that a custom connector isn't verified by them and a malicious server can hide instructions for Claude. Also skip the "hacks" that call HighLevel's internal endpoints to write workflows. They aren't part of the public API, so they can break without warning.
Revoke access when a project ends. Remove the connector in Claude, revoke it from your LeadConnector account, and delete any Private Integration token you made for it.

FAQ
Is there an official GoHighLevel MCP server?+
Yes. HighLevel runs it, also called the LeadConnector MCP server. Claude connects at https://services.leadconnectorhq.com/mcp/anthropic/v2, ChatGPT and Codex at /mcp/openai/v2/ and Cursor at /mcp/cursor/v2.
Does Claude Desktop need mcp-remote or a config file for GoHighLevel?+
No. Add it as a custom connector under Customize > Connectors. Remote connectors are tied to your Claude account, so the same connector shows up in claude.ai, the desktop app and Cowork. The claude_desktop_config.json route is for local servers.
Can Claude send texts and emails from GoHighLevel?+
Yes, if you approved the conversation permissions. It sends through HighLevel like any other message, so A2P rules and message charges apply the same way. Approve sends one at a time until you trust it.
Why does Claude say the workflow API isn't enabled for my location?+
That's the WORKFLOW_API_NOT_ENABLED_FOR_LOCATION error. Workflows in MCP are in private beta as of October 2026, and your sub-account isn't in it. Ask HighLevel support or use the access form in their changelog.
Can one Claude connection work across all my client sub-accounts?+
If you connect as an agency and your sign-in lets you select several sub-accounts, yes. That option is still rolling out. Each request runs in one sub-account, and Claude can't reach any you didn't select.
Is the GoHighLevel MCP read only?+
No. It can create, update and delete across most areas, within the permissions you approve. Forms and surveys are read only, and workflow writing is private beta.
How do I disconnect Claude from GoHighLevel?+
Remove the connector in Claude (in Claude Code, claude mcp logout then claude mcp remove), then revoke the app's access from your LeadConnector account.
